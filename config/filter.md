# 过滤规则字段说明

这个文件说明 `filter.json` 里每个 key 是干什么的。

**一句话原则：这里只放规则，不放记录。**

脚本每次运行都按这里的规则**实时过滤一遍**，跑完**不会往这个文件写任何东西**。
所以这份规则不会越跑越长，改了什么下一轮立刻生效。

---

## 字段

### `filter_keys`

**精确 id 过滤。** 站点的 `key` 命中列表里任意一项 → 剔除。

用途：屏蔽"技术上能跑、但我不要它"的站点。这种只有靠这里能挡住 ——
其他过滤条件（类是否存在、名字正则）都拦不住它们。

匹配方式：完全相等（区分大小写）。

### `filter_name_patterns`

**正则过滤。** 站点的**显示名**只要"包含"任意一条正则 → 剔除。

用途：按名字特征批量挡掉失效的、推广的、占位的站点，不用逐个写 key。

匹配方式：`re.search`（部分匹配）。也就是说写 `测试` 只会命中名字里
**连着的"测试"两个字**，不会因为名字里有个"测"就命中。
写错了正则不会让构建失败，只会打一条警告然后跳过那一条。

### `filter_api_prefixes`

**前缀过滤。** 站点的 `api` 以列表里任意一项**开头** → 剔除。

用途：一整族接口一起挡掉。比如某族接口的 api 都长成 `Xxx...`，
写 `Xxx` 就能把整族挡掉，不用逐个列 key。

匹配方式：`startswith`。

### `filter_hosts`

**域名过滤。** 站点的 `api` / `ext` 里出现的域名命中列表里任意一项 → 剔除。

用途：某个域名下的站点全都不要。

匹配方式：**后缀匹配**。写 `example.com` 会同时挡掉 `a.example.com`
和 `b.example.com`。

### `whitelist_keys`

**例外，不过滤。** 站点的 `key` 命中这里 → **无条件保留**，跳过上面全部检查。

用途：上面某条规则误伤了你想留的站点时，把它的 key 写这里救回来。
优先级最高。

### `only_sources`

**只跑指定的上游源。** 平时留空。

用途：调试。填了之后只抓列表里的源，便于单独排查某个源的问题。

---

## 优先级（顺序不能改）

```
1. whitelist_keys      命中 → 保留（跳过后面全部）
2. filter_keys         命中 → 剔除
3. filter_name_patterns 命中 → 剔除
4. filter_api_prefixes  命中 → 剔除
5. filter_hosts         命中 → 剔除
6. 类不在当前选定的包里   → 剔除
7. key 已被前面的站点占用 → 剔除（保留先出现的那个）
8. 上面的都没命中         → 保留
```

**第 6 条不在这里配。** 它是每次运行**实时**算出来的：拿当时选定的那个包
读出类清单，逐个站点比对。所以：

- 换包之后，结果**下一轮自动跟着变**，没有副作用；
- **不要把它的结论抄进这个文件** —— 那等于把"当时的判断"固化下来，
  以后换了包也放不出来（这里踩过坑：一次换包导致 38 个正常站点被判死并写进规则，永久出不来）。
